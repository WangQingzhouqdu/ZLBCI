常见问题与排查

连接、波形、数据记录和开发交付中常见问题的处理路径。

智链脑机工坊   /   资料整理 2026-10-31

连接类问题

设备搜索不到怎么办？

检查板卡供电与串口广播日志，确认蓝牙已开启且应用有权限。当前固件广播名为 ESP32S3-EEG；Python 扫描默认筛选名称带 EEG 或包含目标服务 UUID 的设备。确认目标板卡未被其他电脑或手机连接。

USB 已连接，为什么上位机没有数据？

当前所整理固件使用 BLE 传输采集数据。USB 在这套源码中用于供电、下载或串口日志，不能把 USB 调试成功等同于 USB 采集链路可用。请按 BLE 流程扫描与连接。

能否同时连接多个上位机？

当前代码以一个连接状态和一组发送特征处理采集，没有给出多客户端并发采集的协议和测试记录。使用一个目标上位机进行联调。

波形与信号问题

已连接但没有波形

检查 START 是否已发送、状态中 stream 是否为 1、数据计数是否递增，以及通道显示开关。先切换 TEST 模式检查链路；若 TEST 正常而 NORMAL 异常，再按硬件图检查外部输入与参考。

通道全零、饱和或偏置很大

核对输入模式、输入范围、增益、公共参考与偏置接法。先断开人体连接，在台架使用已知测试输入，保存未滤波数据定位问题；不要仅用滤波后的曲线判断硬件是否正常。

50 Hz 干扰明显

检查供电、输入终端、导联布置、参考连接和周围干扰源。保留关闭滤波的原始数据，再比较开启陷波后的结果；陷波改善显示不等于硬件噪声指标得到验证。

TEST 模式能证明整板性能吗？

内部测试信号可检查芯片采集、固件打包和上位机显示等环节，不能单独验证外部电极连接器、保护电路或完整模拟输入通路的噪声与精度。

丢样与记录问题

如何判断丢样？

优先检查相邻数据包的样本序号：下一包 sidx 应等于上一包 sidx + n，并处理 uint32 回绕。固件 lost 计数与上位机缺口统计覆盖范围不同；保留两者作为诊断信息，不直接相加。

低 MTU 或高采样率下不稳定

先退回 250 SPS，检查实际 MTU。当前格式一个样本包需要 39 字节通知载荷，对应至少 MTU 42；代码没有为更低 MTU 实现应用层分片。逐级测试更高采样率时记录样本率、缺口与持续时间。

CSV 的 raw_ch 是原始 ADC 码吗？

不是。当前 Python 上位机将 ADC 整数码换算为 µV 后再保存，raw_ch 表示未经过上位机数字滤波的数据。需要整数码时，应在解析器中另行保留并明确文件格式。

记录时能修改采样率或增益吗？

建议停止记录后再修改。固件重新配置会停采并重新开始，样本序号归零；将不同配置写入同一个连续记录会增加时间轴和单位解释的歧义。

产品与交付问题

8 通道意味着只需 8 个电极吗？

8 通道描述测量通道数量。当前固件默认公共参考方案还涉及 SRB1 和偏置连接；实际连接器和电极配置必须依照对应硬件版本确认。

有源码就代表开源吗？

资料中包含源文件，但原资料没有给出统一的开源授权。使用、修改、商用、再分发以及原理图和 PCB 文件的交付范围，需分别确认。

是否包含全部手机和桌面软件？

现有资料包含多个平台的工程与演示内容；标准板卡、软件安装包、定制软件和源码应逐项列入交付清单，不能仅凭目录中有文件判断每个订单的包含范围。

能直接用于诊断、治疗或意念控制吗？

产品资料定位为教学与研发采集平台。诊断和治疗不属于本文档功能；专注度评分、意念控制等属于需要另行定义与验证的算法应用，不能由采集板本身推定实现。

提交问题时附带的信息

  • 板卡型号、硬件版本、固件版本、上位机版本。
  • 操作系统、设备型号、蓝牙适配器与连接方式。
  • 供电方式和完整接线示意图。
  • 采样率、增益、模式、MTU、每包样本数及丢样统计。
  • 可复现的步骤、发生频率、短时原始数据和相关日志。

分享记录前移除姓名、账号和本机个人路径等识别信息，并确认有权提供相关数据。
