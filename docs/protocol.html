BLE 通信协议

当前 v1.0.0 固件的服务、命令、二进制数据帧与状态 JSON。

协议范围与连接流程

以下协议按当前固件和 Python 解析器整理，适用于本次资料中的 8 通道 BLE 实现。数据包没有独立的协议版本字段；对接前使用状态中的 fw 识别固件，并固定双方的文件版本。

  1. 扫描广播名 ESP32S3-EEG 或下列服务 UUID。
  2. 建立连接，订阅 TX 数据特征与 STAT 状态特征的 Notify。
  3. 写入 INFO，检查固件版本、当前配置及协商 MTU。
  4. 按需要逐条写入配置命令，核对返回状态，再发送 START。
  5. 结束时发送 STOP，停止记录并断开连接。

ASCII 控制命令

命令区分大小写。每次写入发送一条 ASCII 命令，可带 CR 或 LF；固件遇到首个换行即结束解析，不把一次写入中的多行视为多条命令。

命令作用注意
START / STOP开始 / 停止采集重新开始会重置样本序号和丢样统计
INFO / PING返回状态 JSON可用于配置回读与心跳
SR:250设置每通道采样率代码接受 250/500/1000/2000/4000/8000/16000
GAIN:24设置 PGA 增益接受 1/2/4/6/8/12/24
MODE:TEST设置输入模式NORMAL / SHORT / TEST / MVDD / TEMP
SRB1:0 或 SRB1:1设置公共参考开关影响所有通道
BIAS:0 或 BIAS:1设置偏置反馈配置根据硬件设计使用
LOFF:0 或 LOFF:1切换导联脱落检测状态返回正、负端掩码
REGS读取 0x00–0x17 寄存器返回 t=regs；采集中会停采后重启

采集中修改采样率、增益或模式等配置会停采、重新配置并重启，样本序号随之归零。建议停止记录后改参数，重新建立一段记录。当前固件没有独立 ACK 编号或结构化错误码，应检查返回状态是否与请求一致。

二进制数据帧

总长度为 14 + n × 8 × 3 + 1 字节。包头整数为小端；每个通道样本保持 ADS1299 的 24 位大端有符号补码。

字节偏移长度字段说明
0–12magic固定 A5 5A
2–32sequint16，小端包序号，自然回绕
41nch通道数，当前为 8
51n本包样本数，当前最多 10
6–94sidxuint32，小端；首个样本的绝对序号
101loffp正端导联脱落状态位图
111loffn负端导联脱落状态位图
121flagsbit0 丢样/溢出，bit1 正在采集，bit2 TEST；bit4–7 为采样率代码
131gainCode0–6 对应 ×1/2/4/6/8/12/24
14 起n × 24samples样本 0 的 CH1…CH8，再样本 1 的 CH1…CH8，以此类推
最后 1 字节1CRC8覆盖包头和所有样本字节，不含 CRC 字节本身

采样率代码 0/1/2/3/4/5/6 对应 250/500/1000/2000/4000/8000/16000 SPS。CRC 多项式 0x07，初值 0x00，逐位左移，不反射，无最终异或。可用 ASCII 字节串 123456789 自检：该实现返回 0xF4。

样本解析与电压换算

# 三字节 b0, b1, b2 按大端解析
raw = (b0 << 16) | (b1 << 8) | b2
if raw & 0x800000:
    raw -= 0x1000000

volts = raw * 4.5 / (gain * 8388608)
microvolts = volts * 1e6

4.5 V 是这套源码采用的参考电压。若实际硬件参考源或增益配置发生变化，须同步调整换算；这个公式不包含整板校准误差。Python 的 parse_packet() 返回的 data 已经是 µV 数组，形状为 (样本数, 通道数)。

MTU、分包与丢样

固件请求 MTU 517，但实际值由连接双方协商决定。单个数据包占用 15 + 24n 字节，Notify 的有效载荷通常为 MTU − 3。

每包样本数数据包长度需要的最小 ATT MTU
139 字节42
6159 字节162
10255 字节258

当前代码把每包样本数至少设为 1，未对 MTU 不足 42 的情况停止发送或自行分片；低 MTU 链路不能据此认为可用。状态 JSON 也以单次 Notify 发送，对接端应检查是否收到完整 JSON。

判断连续性时，比较本包 sidx 与上包 sidx + n，按 uint32 回绕处理。固件发现 DRDY 漏读或环形缓冲满时会增加样本序号；单包内部只发送连续样本，缺口留在包间。包序号 seq 与样本序号含义不同；当前代码在 START 时重置样本序号，但不会同时清零包序号。

环形缓冲定义为 600 个槽位，采用空槽区分满/空；不足整包时约等待 30 ms 后发送。上述是代码行为，不构成端到端延迟或无丢包保证。

状态 JSON

连接期间固件约每秒发送一次状态，已识别的配置与启停命令也会返回状态；REGS 返回独立的寄存器 JSON，未知命令没有结构化错误回复。

{
  "t": "status", "fw": "1.0.0", "id": "0x3E",
  "stream": 0, "sr": 250, "gain": 24, "mode": "NORMAL",
  "srb1": 1, "bias": 1, "loff": 0,
  "mtu": 517, "spp": 10,
  "lost": 0, "idx": 0, "loffp": 0, "loffn": 0
}

idx 是固件当前的下一样本序号，loffp/loffn 是最近一次采集更新的导联状态位图。以上仅为字段示例；id、mtu、计数和运行状态必须以设备实际返回值为准。lost 是固件端记录的漏采/溢出样本数；上位机根据样本序号计算的缺口还可能包含链路损失，二者不能简单相加。

REGS 返回 {"t":"regs","v":[...]}，数组依次对应 0x00–0x17 寄存器。当前配置保存在内存中，源码没有提供用户参数掉电保存功能。
